# Architecture and data invariants

The app has one LibraryModel and one PlaybackService on the main actor. UI queries and import work go through a LibraryDatabase actor; its single SQLite connection owns writes and migrations. The ImportService actor streams one source at a time in 1 MB chunks, hashes during copy, probes AVFoundation asynchronously, downscales artwork through ImageIO, then commits a Song after moving audio into its final managed location. A failed import removes its own files; external originals remain untouched. A content-hash UNIQUE constraint is the final duplicate authority. Duplicate encodings/tags with different bytes are intentionally distinct.

Documents contains Music (UUID filenames), Import (user-managed file-sharing inbox), and LibraryData (SQLite WAL database, bounded-size artwork and lyric text). Paths in the index are relative, so app-container changes during a correctly recognized update do not invalidate them. Automatic cloud backup is disabled and audio protection permits reading after first unlock since boot. No app source uses URLSession, HTTP playback or telemetry.

SQLite stores searchable/sortable scalar columns and a Codable Song payload. Queries fetch 100-row UI pages; building a playback queue fetches IDs rather than all audio or artwork. A queue entry UUID is independent of a song ID. Original order is persisted for shuffle reversal, and repeated songs are safe. AVQueuePlayer holds only the current and next audio items; generation tokens reject stale asynchronous loads after user queue changes. Current-item observation advances logical identity and replenishes the next item. Repeat-one preloads a fresh item for the same entry. Metadata, elapsed anchors and artwork go through MPNowPlayingInfoCenter; remote handlers invoke the same service actions as buttons.

The queue snapshot is stored on structural edits and track changes. A separate small position state updates every ten playback seconds, on seeking, pause and scene changes; the full queue JSON is not rewritten each timer tick. Restores are paused. A single periodic player observer drives progress and lyric highlighting. The LRC parser sorts and merges timestamps; an upper-bound binary search finds the active line. Manual lyric flags prevent automatic replacement by subsequent imports.

Versioned schema creation is transactional. Opening an unknown newer schema fails visibly with files intact. No destructive reset path exists. SQLite's online backup API captures a consistent index. Restore is an explicit, closed-app user operation documented in README. Process termination between file move and DB commit can leave an orphan; there is deliberately no automatic purge of unknown user files. Deletion stages the audio, removes the index row, and rolls back the move on database failure; failed post-commit cleanup may leave reclaimable bytes, not erase another song. Settings checks for missing files without deleting index rows; exact reimport repairs them.

Swift language mode is 5 with targeted concurrency checks on Xcode 16.4 to keep Apple framework callback interop straightforward. Swift 6 strict mode is a future migration, not silently enabled. The app itself has no third-party packages. XcodeGen and Pillow (icon regeneration only) are build/development tools. GitHub receives source, not the user's library. Local Logger errors assist diagnosis without uploading logs.
